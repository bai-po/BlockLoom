# OXAL 资源导入规范

这是资源导入规则的唯一维护入口，适用于 `.blend`、图片、外部模型及材质包等后端。具体导入算法由业务工具实现，不要求所有资源使用同一种读取 API。

## 开始工作

1. 定位项目并读取 [AGENTS.md](../../../AGENTS.md#核心修改权限先于业务任务执行)，先确认业务执行者的核心只读边界。资源工具及共用算法分别在 `business/` 和 `util/` 按任务维护；资源优化不授权修改 `core/` 内的端点或调度。已有能力不足时按 AGENTS.md 报告。规范本身也不授权接通新业务。
2. 设计或修改导入时，读 [详细规范](references/standard.md)，按实际任务使用其中的策略、读取、事务及验收章节。
3. 需要接入按钮、Topic、EMT、回调、生命周期或 Blender Undo 时，使用相邻的 [$oxal-bus](../oxal-bus/SKILL.md)。本 Skill 不定义另一套总线流程。
4. 新建工具时按需复制 [工具骨架](assets/tool.py.example) 到项目 `business/<domain>/<name>.py`，实现对应业务钩子；已有工具只修改所需部分，不为套模板整体重写。

导入入口、结果及持久资源身份的变更遵循 [业务公开接口与兼容](../oxal-project/SKILL.md#业务公开接口与兼容)；复用算法遵循 [util 的职责与依赖](../oxal-project/SKILL.md#util-的职责与依赖)。移动实现或修改接口后，按 [配套内容同步维护](../oxal-project/SKILL.md#配套内容同步维护) 核对模板、参考和仍在使用的开发工具。

## 先确定资源语义

为每个导入声明稳定的 `asset_id`、兼容版本、策略、作用域、来源与入口。再区分：

| 策略 | 适用行为 |
| --- | --- |
| `ACTIVATE_EXISTING` | 验证并激活作用域内已有的完整实例，如天空 |
| `NEW_INSTANCE` | 每次创建新的可编辑实例，如人模或物品；可按契约复用模板 |
| `REUSE_DATABLOCK` | 按逻辑身份、版本、变体和可变性共享材质、图片等依赖 |

实例是否新建与依赖是否共享是两个决定。不能把所有导入都变成“已有就直接返回”，也不能为独立实例盲目复制全部只读依赖。

资源完整性与作用域检查先于源文件读取；同一业务需要同一 `.blend` 的多个入口时合并读取计划。局部准备后再发布到目标，集中做必要更新。

修改已有状态前记录恢复方式；失败只清理本次确认拥有的数据。全工程新增差集和名称都不是拥有权证明。具体依据见详细规范的“事务与清理”。

## 模板与现有实现

骨架中的类型和钩子只是资源流程示例，未实现时明确失败，不自动登记或读取资源。它不是可直接传给现有 `ImportEndpoint` 的适配器：按 Bus Skill 的实际加载签名和项目结果类型接入，不照抄一套重复端点。

- [天空工具](../../../business/sky/sky.py)：已有实例激活与首次读取的参考。
- [人模工具](../../../business/human/human.py)、[物品栏工具](../../../business/inventory/inventory.py)：独立可编辑实例与依赖处理的参考。
- [追加事务](../../../util/resources.py)：现有来源归属及清理实现；复用前核对适用边界。
- 按实际改动验证天空、独立实例等资源行为；临时验证文件与产物使用 AGENTS.md 规定的 `_test` 后缀，用完清理，不随 Git 分发。不得假定仓库自带测试脚本或保留指向已清理测试的链接。

参考实现代表已实现的范围。模板复制、统一材质管理或其它缓存方案只有代码实际支持时才能当作现成能力。

## 验证与交接

测试代码、临时演示及其产物统一遵循 [项目测试约定](../oxal-project/SKILL.md#测试代码与产物)，包括 `_test` 命名、Git/打包排除、单向依赖、无测试依赖的交付、实际结果与用后清理。

按详细规范验证所改策略、首次/重复导入、失败恢复、依赖与多实例隔离；涉及持久数据时验证保存重开，涉及撤销时按 Bus Skill 验证原生 Undo/Redo。

性能报告区分业务、库读取、准备/更新、原生执行与撤销开销、排队及回调总耗时。比较双方保持资源、选项和功能一致；首次与复用分开，不把延后回复当成计算加速。

检查范围随变更选择。仅整理 Skill/文档时校验结构、链接和示例，不启动 Blender、导入资产或触发热加载。实际代码改动的检查与交付遵循项目要求。

在对话中简要说明策略、共享/复制边界、事务拥有权、适用测试与实测限制；说明尚未实现的优化，不另建交付或性能报告文档。项目整理和交付遵循 [$oxal-project](../oxal-project/SKILL.md)。
