# 测试产物与磁盘治理

目标：完成任务要求的真实验证，同时让本次新增存储有预算、有归属、可核对、能收尾。节省的是重复副本和无用途的残留，不是测试覆盖率、失败证据或用户明确要求的长录屏。

这是执行规范，不是自动磁盘配额或清理器。仅安装此 Skill 不会监控磁盘、强制停止进程或删除文件。只有已经实施并验证的执行器、配额、监控和清理动作，才可称为已生效的技术保障。

## 先处理既有规则与目标

- 先读实际目标根的 `AGENTS.md` 和相关测试规范。在 OXAL 中，已有 `oxal-project` 管测试命名、无测试依赖交付及清理，`oxal-bus` 管 EMT 验证。这里仅补充产物容量和生命周期的执行检查，不另定核心权限、Bus 契约或发布规则，不覆盖现有 Skill。
- 核对任务指定位置、工作目录、仓库根、规范中的维护路径和必要时的运行时模块路径。旧目录、迁移副本或规范指向的目录缺失时，先澄清写入目标。Git 或路径读取被安全机制拒绝时，保留限制，不改安全设置或换路线绕过。
- 纯规范、文档或忽略规则修改，只做相应内容、链接与范围校验，不为此启动 Blender、复制仓库或创建回归环境。
- 本 Skill 不授予删除历史文件、修改用户工程、安装软件、提高测试负载或发布的权限。现有授权不足时先询问，不把“节省磁盘”作为扩大权限的理由。

## 一、写入前做可执行的预算

在对话或已有任务记录中列明以下内容，不另建进度报告：

1. 验证目标、真实版本矩阵和必要证据。区别静态检查、直接源码运行、真实安装启用和业务回归；不把其中一种冒充另一种。
2. 复用的输入，以及本次新建或会修改的绝对路径。包括项目外的临时目录、解压器暂存、用户配置、应用缓存、崩溃转储和编码临时文件；不能只统计 `.dev`。
3. 峰值新增逻辑字节、文件数、同时存在的安装树/候选包/工程副本数，以及各目标卷当前可用空间。数据来自归档条目、已有同类产物或有代表性的受控试运行；标明未知量。
4. 本任务的增长预算、最大并存副本数、必要磁盘预留量、观测时点和超限动作。数字按实际任务规模、用户目标和机器状态设定并说明依据，不声称存在官方统一 GiB、时长或副本上限。已有明确授权范围内的合理预算可直接采用；若必须缩减用户要求或增加成本/权限，先确认。

估算时计算同时存在的峰值：下载包 + 解压树 + 各隔离安装树 + 构建/打包暂存 + 场景/备份 + 输出/日志/录屏。计入多版本、并发进程及必要失败复现副本，避免把压缩包大小当成展开大小。归档声明大小只是预估，不是安全保证；不为估算先无约束地完整解压。

对于每个目标卷，下一阶段启动条件是：

`当前可用空间 - 其它任务已预留但尚未写入的容量 - 本阶段至结束的预计新增峰值 >= 必须保留的空间`

避免重复扣除已经落盘的占用。预留应容纳正常系统运行、其他活跃任务和安全停止/保存必要证据的空间。不能把一次 `disk_usage` 查询当成持续保证，也不能把所有空闲空间视为本任务独占。小文件场景同时考虑文件数、可用 inode（适用时）及目录操作成本；逻辑大小不能直接代表实际分配空间。

**开始条件不满足：** 不启动新的展开、复制、构建或录制。先减少没有验证用途的并存副本、串行调度或调整输出位置，再重新估算。必要验证仍放不下时明确阻塞并请用户选择，不能偷偷跳过测试或清理未知文件。

## 二、一个任务容器，版本与并发各自隔离

- 优先沿用项目认可的临时根，例如 OXAL 的 `.dev/`。原子创建一个带任务标识和随机唯一标识的 `<task>-<unique>_test/`，存在则检查归属，不覆盖。文件和目录命名继续服从项目规则。
- 在该任务目录内按版本、独立运行及并发 worker 分配写入位置。例如 `blender-4.5/run-01/worker-00/`，由最外层 `_test` 容器统一隔离。不要把 `current`、`latest2` 之类共享可写位置当作并发工作区。
- 每个工作进程有确定的拥有者、写入范围和生命周期。记录实际输出路径、初始文件数/逻辑大小及进程身份；路径由工具重定向时同步更新。使用当前上下文或已有任务记录，需要崩溃恢复时才保存最小机器可读归属记录，不堆叠报告。
- 新运行只在前一个进程及其子进程确已停止、位置不再使用且归属明确时复用本任务目录。不得以“目录很旧”“PID 不存在”单独认定可删，PID 可能重用，产物可能供另一任务读取。
- 同卷并发任务要协调总预算，使用已有调度器、可靠的互斥/预留机制或串行执行大写入阶段。多个 worker 分别看到足够空闲空间，不等于总量可承受。跨任务不能协调时采用串行或有依据的保守预留；无法可信界定总需求就暂停，不能猜测其他任务占用，也不能靠无锁 `latest` 文件宣布协调完成。串行仍须把前一阶段必须保留的输出计入后一阶段预算，不保证总量一定放得下。

## 三、复用不可变输入，保留真实测试隔离

- 按精确版本、来源和必要的内容校验复用已验证的 Blender 运行时、下载包及不可变素材；不要为每个用例重新下载相同文件或复制整仓。已有可用安装不自动授权更改它。
- 共享可执行文件不等于共享可写状态。独立隔离应用用户配置、偏好、插件安装位置、扩展仓库、缓存、临时文件和会保存的工程。使用当前工具/版本支持的路径配置，并核对实际生效位置，不凭设置了环境变量就认定全部隔离。
- 需要真实安装回归时仍从实际拟交付包安装；不能把指向开发源码的链接或直接 `register()` 称为安装验证。覆盖声明支持的版本与实际受影响的行为，纯文档改动例外按既有规则执行。
- 不可变输入通过链接复用前核对工具是否会写入、链接目标和生命周期。硬链接共享同一底层文件，修改它可污染原件，不能代替写隔离。会被 Blender 保存、备份或重写的 `.blend` 应使用独立可写副本。
- Windows junction、符号链接和其它 reparse point 不作为普通目录递归展开。禁止建立指回项目根或祖先的递归链接；扫描、打包和清理必须明确跳过链接或使用经验证的“不跟随”策略。遇到无法辨别的链接先停，不用跨 shell 拼接命令删除。
- 工具不能确保输入只读或写状态隔离时，保留必要独立副本并计入预算。节省空间不得牺牲隔离或污染用户工作工程。

## 四、运行中监测，达到预算就停止扩大

- 只统计本任务实际写入范围，不为每次检查扫描整个历史 `.dev`。在大解压/复制前、构建阶段切换和录制分段时检查实际增长和目标卷空间；长运行按预计增长速度安排周期检查。
- 将日志、截图、崩溃转储及失败重试计入预算。长视频按用户要求保留时长、必要画质和关键过程，通过合适编码、分段写入和复用输入控制峰值，不擅自改成短截图或删减场景。支持完整证据的分段也不能在验收前自动删除。
- 每次重试先判断是否有新证据或代码变化，能否复用本任务已停止的位置。没有新信息且结果稳定时不无限重跑。新增版本、用例或副本前更新峰值估算。
- 当实际增长超预算、剩余空间触及预留量、文件数异常、输出落在未知位置或出现失控递归时，立即停止启动新的大写入阶段；安全停止本任务的产物生成进程，保留必要失败信息并报告阻塞。不要杀死其它用户进程，不为补证据继续写满磁盘。
- 若工具无法中断或持续观察写入，启动前说明限制。根据有依据的最坏峰值分段/串行执行；不能证明可在可用空间内完成且后果明显时先暂停。规范中的“停止”要求不是已经存在的技术熔断器。

## 五、成功清理，失败有界保留

**清理前四项均须成立：** 路径是本任务创建/拥有的；当前授权允许处理；没有活跃进程或其他任务使用；目标及各父路径不越过允许范围或链接边界。使用解析后的绝对路径和组件级包含关系，不用字符串前缀判断目录归属。存在并发替换风险时先协调并重新检查；不能可靠确定边界就停。

- 成功后，核验交付物及已请求证据确已保存到正确位置，再清理本任务不再需要的安装展开树、候选包、临时工程、测试代码和输出。用户要求保留的交付件不属于待清理临时物。
- **OXAL 工作区的废弃文件用剪切收尾。** 考虑到删除权限限制，已确认废弃的本任务文件直接移入工作区根目录的 `废弃文件/`（当前为 `D:\codex\OXAL\废弃文件`），无需先尝试删除。目标目录缺失时创建；若整个任务目录均可废弃，保留原目录名整体移动。混有交付件、仍需保留的证据或其他任务文件时，只移动已确认废弃的条目。
- 核对源和目标的绝对路径及链接边界后，执行同卷移动（Windows 可用 `Move-Item -LiteralPath`）。目标重名时使用含任务标识的唯一名称，保留目标已有内容。完成后确认源路径已消失、目标可读，目录的文件数和总字节数与移动前一致。在对话中报告实际去向；同卷移动不释放磁盘空间。移动本身被拒绝或结果不明时，保留现场并报告，不改为复制后删除。
- 失败或仍在排查时，保留能复现问题的最小集合：版本/构建身份、执行条件、关键日志以及必要输入/场景。只保存差异不足以复现时保留完整必要工程；不因失败而复制所有历史环境。
- 运行前确定失败保留的用途、数量/容量预算和复查或到期条件，按真实复现需求选择值。达到保留预算后停止继续累积，报告还需空间或决定，不能自动删除唯一失败证据。到期只触发复查；后续实际删除仍需核实授权、归属与用途，不创建未经用户请求的定时清理任务。
- 中断、崩溃和 `finally` 都不保证外部程序已停止或目录已移除。Windows 文件句柄未释放、权限错误、未知归属或清理结果不明时，保留并报告具体路径/原因，不循环强删。
- 不因目录名含 `test`、被 Git 忽略、体积很大或压缩包读取失败就认定无价值。不清理历史 `.dev`、旧备份、共享运行时、开发环境、用户素材和其他任务文件。历史整理必须另有明确范围及授权；“相同大小/名称”不是重复证明。
- 不把压缩、移动到另一目录、改忽略规则或隐藏文件称为已释放空间。清理后核对目标状态和实际释放情况，区别逻辑大小与卷可用空间变化，注明并发写入的影响。

pytest 的 `--basetemp` 会清空指定目录，只能指向本次运行独占的临时目录。详见 [pytest 临时目录说明](https://docs.pytest.org/en/stable/how-to/tmp_path.html#temporary-directory-location-and-retention)。使用 Python 临时目录时，按所用 API 核对清理责任，见 [Python tempfile 文档](https://docs.python.org/3/library/tempfile.html)。

## 六、完成时给出可核查的结果

直接在对话报告，不默认写阶段报告。至少回答：

- 实测的版本/行为、失败和未测范围；静态检查是否与真实安装/运行分开说明。
- 本任务实际写入路径、峰值的观测值或未观测限制、最终文件数/逻辑大小、安装树和候选包数量；相对预算的偏差。
- 哪些本任务产物已核实删除；哪些仍保留、大小/数量、用途、后续处理条件；哪些因权限或归属不明未处理。
- 正式源码、资源和交付包不依赖临时测试文件，测试未混入交付；Git/打包范围核查是否受阻。

任何必要项未执行或无法核实都明确标为未完成/未核实。不能把 `.gitignore` 命中当成磁盘清理，也不能因空间合规而宣布未跑的回归通过。
