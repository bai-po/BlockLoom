# OXAL 项目通用规范

## GitHub 仓库

BlockLoom 插件源码发布到 `https://github.com/bai-po/BlockLoom.git` 的 `main` 分支。插件安装包上传到同仓库对应版本的 GitHub Release。网站部署包在本地单独交付。

发布时使用仓库所有者 `bai-po` 已认证的个人账号。推送前确认 Git 提交的作者和提交者都关联该账号；创建 Release 和上传安装包时也使用该账号。发布后核对 GitHub 返回的提交作者、提交者、Release 发布者和附件上传者。不使用 `github-actions[bot]` 代为发布；本机缺少个人账号授权时，请用户在 GitHub 官方登录页完成认证。

先读项目根目录的 `AGENTS.md`。这是通用工作约定；具体实现按任务使用 [$oxal-bus](../oxal-bus/SKILL.md) 或 [$oxal-resource-import](../oxal-resource-import/SKILL.md)，不在这里复制接口和业务规则。

## 先判定修改权限

先执行 [AGENTS.md 的核心修改权限](../../../AGENTS.md#核心修改权限先于业务任务执行)。默认按业务执行者处理；“优化、修 bug、提升安全、功能开发”不包含核心授权。本 Skill 不授予核心维护权限，也不允许把共用算法整理进 `core/`；任务涉及的业务共用算法在 `util/` 维护。

开始修改前列出目标文件；完成后检查完整差异与受保护路径。接口不支持时完成独立部分，报告具体缺口；不得改核心、在业务目录复制核心或改规则放行。核心恢复目标和已授权例外只在 AGENTS.md 维护，不在各 Skill 重新解释。

## 天空专属代码只读

- 天空 UI 和逻辑默认只读，包括 `ui/sky.py`、`operation/sky.py`、`module/sky.py`、`business/sky/`，以及其他文件中专门实现天空行为的代码（含 `util/` 内的天空专用辅助函数）。保护涵盖新增、修改、删除、移动、重命名和格式化，也适用于脚本或子代理代为执行的改动。
- 混合文件按实际改动的函数、分支或登记项判断。先看职责和调用方。其他模块与天空共用的工具、UI 组件和登记机制按原有权限维护。这里只修改共享实现或其他模块自己的部分时，即使天空也调用它，也不触发天空提醒。若同一改动还会改写天空专属分支或登记项，则触发提醒。原有核心权限仍然适用。
- 每次请求涉及写入天空专属代码时，先提醒用户该部分默认只读，点明本次要改的文件或符号和目的，然后停下。本次请求在用户回应前只做只读检查，不执行任何更改。用户在提醒后明确放行，才执行本次说明范围内的操作。新的操作或扩大的范围须重新提醒，历史修复授权不沿用。单纯阅读、排查或调用现有公开接口无需放行。

## 业务公开接口与兼容

- 修改前识别任务涉及的公开入口和实际使用者：供其他业务或用户脚本调用的入口函数、Topic 与 payload/结果/错误约定、Operator `bl_idname`，以及保存到 `.blend` 的属性名、资源身份和动画/驱动引用。内部辅助函数不自动成为公共 API；按调用、登记和保存方式判定，不能只看命名。
- 内部优化默认保持已有调用方式、参数默认值、结果形状和成功/失败语义，以及已有工程中的持久引用。目录单数命名不要求改动 `assets.execute` 等公开标识，也不授权重命名资源身份或持久属性。
- 任务明确要求改变接口或迁移数据时，在已有授权范围内更新调用方、文档和必要迁移，并验证受影响的旧调用或工程；不得静默丢弃旧字段、覆盖用户数据或把失败改报成功。超出任务范围的兼容问题先说明具体影响，不顺带扩展修改；授权不会扩大到 EMT 核心。

## util 的职责与依赖

- `util/` 容纳与具体业务流程无关的共用辅助能力；是否进入此目录按职责判断，不能仅凭两个调用方决定。按业务选择操作、组织跨业务动作或组合业务流程的代码留在 `business/`，登记与协调仍由 `module/` 负责。
- `business/`、`module/`、`operation/`、`ui/` 可按职责调用 `util/`；`util/` 不通过直接/动态导入或按名称查找反向依赖这些上层，不在共用工具中登记、调度或发起具体业务。新增依赖前检查是否形成循环；核心边界继续按 AGENTS.md 执行。
- 遇到已有反向引用先说明具体调用关系，只在任务授权范围内调整；不为落实规范全面搬文件、重写算法或给核心增加适配层。

## 配套内容同步维护

- 移动目录、修改公开接口或删除功能时，检索相关 Markdown 链接、代码示例、点号模块路径、动态导入字符串、命令和开发工具检查项，核对实际目标及当前登记。不能只改斜杠路径就认为同步完成。
- 在同一任务中修正受影响的 README、所属 Skills/参考、模板和仍在使用的本地开发工具；共享规范只维护一份，其它位置引用。历史源码快照、外部工具代码和标准资源目录按其原用途保留；合法的局部变量别名不按旧目录名机械替换。
- 以实际源码与授权范围核实冲突；过时说明修正或删除，不为迎合旧文档改核心，也不把待恢复目标写成已经实现。交付前校验相关链接、示例和工具；修改工具脚本时验证语法、导入目标和对应检查逻辑，如实说明未运行的 Blender 操作，不因文档或开发工具路径修正对用户工程触发热加载。

## 文档与交付

- 默认不创建阶段性报告、开发总结、任务完成清单、迁移报告、验收报告、性能报告或交接用 Markdown 文件。用户明确要求某一文档时再创建。
- 完成情况、验证结果、计时和剩余限制直接在对话里简要说明。不得把这类报告改名或搬到 `docs/`、`.agents/` 等目录继续堆积。
- 可复用开发规范维护在对应 Skill；必要的项目入口或长期使用说明按实际需要维护。不要为每次任务新增 README、规范副本或旧路径跳转页。
- `core/` 只放 EMT 运行代码，不新增 README、API 说明或其它 Markdown 文档；核心目录职责与接口介绍并入 [Bus API 参考](../oxal-bus/references/api.md)。其它目录需要长期说明时按需维护其已有 README，不重复建立说明文件。
- 只把影响后续开发的稳定约定补进已有规范；不把本次运行记录、进度或聊天流水写进去。

## 目录与 Git 范围

- 根目录保留插件入口、清单、依赖/工具配置、`AGENTS.md` 及实际代码和资源目录。AI 规范集中在 `.agents/skills/`，复用模板放进所属 Skill 的 `assets/`。
- 临时脚本、截图、测试输出和原始计时数据按需放到已忽略的 `.dev/`，不再为它们生成总结文档；测试的命名、执行和清理遵循下方“测试代码与产物”。
- Git 保留业务源码、必要资源与来源元数据、`.agents/skills/`、`AGENTS.md`、`pyproject.toml`、`uv.lock` 和可移植工具配置。
- `.venv/`、Python/检查器缓存、本机路径与调试配置、临时日志、构建产物及 Blender 自动备份由 `.gitignore` 排除。本机设置可以继续存在，不必删除或改写用户配置。
- 不用 `*.md`、`*.json` 或 `*.blend` 这种宽泛规则隐藏项目必须提交的内容。资源是否随包按实际运行依赖判断，不因它是二进制就排除。
- `.gitignore` 不会自动取消已跟踪文件；调整时检查索引。除非任务要求，不代替用户创建提交、推送或发布。

仅更改规范、文档或忽略规则时校验链接和 Git 范围即可，不启动 Blender、不导入资源、不热加载。

## 每次任务的存储执行与验收

本节落实下方“测试代码与产物”的创建、清理和交付要求。只管理当前任务确认拥有的产物，不授权整理历史目录、用户工程或其他任务文件。Git 忽略不代表文件已清理，也不代表允许删除。

1. **确认实际项目根。** 修改前核对工作目录、根 AGENTS.md 声明的维护目录及任务指定目标；Git 可用时核对仓库根和已有改动，涉及运行时修改时按既有热加载规则核对 Blender 实际模块路径。检查相关路径是否为链接及其目标。路径不存在、身份冲突或主副本不明时，停止依赖该根目录的写入，报告具体证据，不按旧记录、目录名或磁盘大小猜测。命令被拒绝时保留该限制，不修改 Git 安全设置或 ACL 来继续。

2. **创建前列明成本。** 在对话中简述本任务工作目录、所需 Blender 版本与检查、拟生成的安装展开树、候选包和测试工程，以及可以复用的现有输入。根据安装包条目、已有同类产物或其他可读取元数据估算新增文件数和逻辑字节数，计入版本数、同时保留的副本数及工程备份；压缩包大小不能代替展开大小。标明估算依据和未知项，不为估算先展开整套资源，也不使用固定容量阈值套用所有任务。无文件产物的规范修改直接说明无需创建测试目录。

3. **明确任务归属与基线。** 临时产物集中在一个 `.dev/<任务>_test/`，版本、用例和必要重试放在其子目录。创建前检查同名目录是否存在；只有确认属于同一任务且用途兼容时才复用，不能覆盖不明归属内容。记录任务实际写入路径及这些路径的初始文件数、逻辑大小；新目录基线为零。工作清单保留在当前执行上下文，不因此新增报告文件。源码和正式资源仍在原业务位置维护，不能复制整仓到任务目录代替修改。

4. **复用输入，保持测试隔离。** 下载包、已核验的运行时和不可变资源按版本、来源与必要的内容标识复用，先检查适用性再下载或复制。各 Blender 版本、安装验证及会写入的配置、缓存、工程和插件安装位置仍按既有规则隔离。不得把可写测试安装树或配置跨运行共享，不把复用源码导入称为完成真实安装验证。链接到共享输入前确认只读使用、目标和生命周期；不得建立指回项目或祖先目录的递归链接，也不能让删除任务目录影响共享目标。工具不能保证隔离或只读时，保留必要独立副本并计入估算。

5. **控制候选与重试副本。** 候选包和重试安装树留在任务目录内；正式交付沿用已有交付入口，不新增平行的发布目录。每份并存副本须有当前验证用途，例如不同版本隔离、前后对照或失败复现。重试前判断能否安全复用已停止使用的本任务位置，不能每轮机械新增 current、latest2、latest3 或整套安装树。需要增加副本或验证范围时，先更新估算并说明原因；涉及额外授权的操作仍按既有权限执行。对已经失去用途的本任务副本按下方清理规则处理，不触碰历史副本。相同文件名或大小仅作为重复候选，必要时核验内容；不能据此删除不同工程、备份或版本。

6. **结束前核对实际增量。** 检查本任务全部实际写入路径，报告新增路径、安装展开树和候选包数量、文件数与逻辑字节增量，以及相对估算的明显偏差。只统计受影响范围，不为普通任务反复扫描整个 `.dev`。不跟随外部或递归链接；硬链接、无法读取路径或其他覆盖限制须说明，不能将路径逻辑大小当成唯一物理占用。对已有并发改动或未知归属内容，不能把目录净增量全部归因于本任务；结合任务工作清单说明已确认部分。

7. **清理与必要保留。** 先核对绝对路径、任务归属、使用状态和链接边界。已确认废弃的本任务产物按[测试产物技能的收尾规则](../test-artifact-storage/SKILL.md#五成功清理失败有界保留)剪切到工作区根目录的 `废弃文件/`。历史测试、开发环境、共享缓存、正式资源和用户工程不在本任务的清理范围内。保留失败复现所需的证据，在对话中说明保留项的位置、大小或数量、用途和后续处理条件。

8. **交付条件。** 按下方“无测试依赖的交付核对”检查正式依赖和打包范围；不能靠本地忽略文件补齐正式功能。对当前任务须能交代：实际目标根已确认；创建范围和副本数有依据；实际增量已核对；每个残留产物有归属及保留理由；已执行清理与未完成项分别说明。Git、权限或运行环境使某项无法核实时，明确标为未核实，不宣称全部验收完成。纯规范修改只检查内容、链接、一致性与修改范围，不启动 Blender、构建或额外测试框架。

## 测试代码与产物

测试会生成安装树、临时工程、日志或录屏等产物时，同时遵循[测试产物与磁盘治理](../test-artifact-storage/SKILL.md)。

以下是 AGENTS.md 中测试约定的执行细则，适用于测试脚本、临时演示、性能验证以及它们生成的日志、截图、JSON 和临时工程。

1. **命名与存放。** 自行命名的文件在扩展名前加 `_test`，如 `sky_test.py`、`result_test.json`；无扩展名文件和文件夹以 `_test` 结尾，如 `sky_test/`。优先放入 `.dev/<用途>_test/`。工具必须使用固定名称的输出放在该目录内，由目录统一排除。正式源码和随包资源不使用此标记；不得在 `core/` 中新增测试文件。
2. **自动排除。** 使用根 `.gitignore` 的 `*_test`、`*_test.*` 通配规则，匹配任意层级的测试文件及目录；打包排除规则保持一致，不为每个测试单独添加路径。用 `git check-ignore --no-index -v -- <路径>` 确认匹配，再用 `git ls-files -- <路径>` 确认未被跟踪。已跟踪文件不会因新增忽略规则自动退出索引。不得使用 `git add -f`、改名或放宽排除规则把测试混入提交或安装包。
3. **创建范围。** 根据当前改动选择必要验证，优先复用实际存在且适用的检查；需要脚本时按需创建，不自动建立常驻测试目录或框架。不得假定已清理的脚本仍然存在。仅修改文档、Skills 或忽略规则时，检查内容、链接和匹配范围即可。
4. **单向依赖与接入。** 测试可调用正式公开 API 和 EMT 接口；正式代码不得反向导入、调用或自动发现测试模块，也不得依赖测试定义的类型、注册副作用或生成的配置。正式功能需要的共用能力属于正常源码，不能藏在测试文件中。测试按钮、Operator、Topic（包括 `demo.sum`）、timer、handler 由独立测试入口管理，不接入插件默认注册和 UI；移除测试不得要求再次改动正式入口。测试不扩大修改权限，核心边界仍按 AGENTS.md 执行；业务执行者不得以测试为由修改核心、放宽保护或加入生产测试开关。
5. **构建、发布与维护者使用。** 编译检查、依赖解析、打包、安装、启停和正式功能不得依赖被 Git 忽略的测试脚本、测试专用依赖、样例资源、缓存、日志或生成文件；正式必需内容随源码维护，不依赖测试先运行一次。发布入口和共享检查不得硬编码维护者本地路径或调用未分发的脚本。其他贡献者从干净检出应能直接使用插件，并依据已有 README 或 Skills 中公开的接口、操作步骤和预期结果执行必要验证。忽略本地测试不等于共享了同一套自动化回归；确需共享该套回归时，另行明确交付方式，不声称缺失脚本可运行，也不删除失败的必要检查来迁就缺失依赖。
6. **运行与结果。** 会增删 Blender 数据的测试使用临时工程和独立配置，不操作用户当前工作工程或覆盖随包原始资源。当前开发实例的热加载继续遵循既有授权与场景保留约定。直接报告实际执行的检查、版本、结果和未测范围；不得通过删断言、跳过失败、改变预期或吞异常宣称通过。检查通过后，不在没有新改动或未解决问题时重复扩大测试。
在用户日常使用的本机执行验证时，默认采用低负载：渲染不超过 64×64、1–4 采样、单帧，CPU 最多 2 线程；只运行一个渲染进程，验证所需动画时仅用最少帧数。不得为等待截图、UI 操作或取消输入而扩大渲染负载。测试超时后停止本任务进程并说明未验证项，不能反复延长重负载任务。确需提高分辨率、采样、线程或执行性能压力测试时，先说明必要性、预计负载与时长，在已有明确授权范围内执行；普通功能验证不包含这类授权。

7. **清理。** 使用完毕清理本任务生成的测试代码、演示、临时工程、日志、截图和缓存；需要继续排查时保留必要证据并说明原因。清理前确认路径和归属，不删除正式资源、用户工程、开发环境、热加载工具或其他任务的文件。失败结果须如实说明，不能用清理掩盖失败，也不默认生成额外测试报告文档。
8. **无测试依赖的交付核对。** 检查 Git 差异、索引、正式导入与构建引用以及打包范围，确认测试未混入正式交付。涉及测试接入、依赖或构建变更时，从仅含拟交付源码与必需资源的临时副本或安装包验证相应构建、安装启用和业务行为；不能利用原工作目录中的隐藏测试、缓存或本机路径补足缺项。不要靠删除用户工作目录来模拟干净环境。纯规范修改只校验规则与引用，不额外创建测试框架。只报告实际完成的清理和验证，不将文件被忽略视为已被删除，也不将静态检查称为已完成安装或运行验收。

## 多版本兼容

- 最低版本以扩展清单为准；对声明支持的 Blender 版本线分别使用实际运行时验证，不能把最低版本的一次测试或直接调用 `register()` 当作其它版本的启用验收。
- 测试使用隔离配置、扩展仓库和工程，覆盖真实安装/启用、重复启停、失败回滚、四个模块的导入、原生动画、Undo/Redo、保存重开和渲染安全；接线细则仍引用 Bus Skill。
- 原生 API 布局差异集中在共用能力适配层，以真实 RNA 能力和数据契约识别；不能捕获异常后跳过功能、用失效驱动的 `valid` 标志代替实际帧值，也不扩大到未经验证的未来版本。
- 在对话中列明实测版本与未测边界。便携测试运行时及校验信息留在 `.dev/`，不修改用户安装、不默认保存用户偏好。
