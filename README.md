# BlockLoom

BlockLoom 是 OXAL 团队面向 Blender 的 Minecraft 风格资产工具，围绕白珀人模、OXAL 天空、OXAL 物品栏与资产库展开开发。

本分支为 **BlockLoom_V0.1.40-Beta**，支持 **Blender 4.5、5.0、5.1、5.2**，按各版本线分别进行真实安装、启用和运行回归。

安装包使用离线生成、像素一致的无损 WebP 资产缩略图，保留原分辨率与透明度。原始 PNG 留在源码仓库；未参与运行的模板源快照已清理，可从 Git 历史追溯。实际运行模板及旧人模兼容资源继续随包提供。

0.1.34 将六份内容完全一致的新版二层描述合并为 `LAYER_RESOLUTION_UNIFIED.json`，旧人模兼容资源集中在 `asset/human/legacy/`。十一份 `.blend` 只重新编码原生可寻址 Zstandard 压缩容器，解压后的 Blender 文件字节与原 Git 资源一致；网格、控制器、动画、材质及内嵌贴图不变。原件哈希、现容器哈希及解码内容哈希记录在 `asset/CONTAINERS.json`。运行时直接由 Blender 读取，不增加解压缓存、下载步骤或 Python 运行依赖。

新版采用独立的 Beta 版本序列。旧插件作为功能、骨骼控制形式和不可变资源参考，业务逻辑按新架构重新实现；不自动迁移旧工程。

人模实例列表同时显示 Beta 与已识别的旧版白珀人模，并以稳定骨架身份选择编辑目标；面板显示“选中：V…”及“已开启兼容模式”，列表下方显示“最新版：V…”。兼容模式保留原骨架、网格及动画，支持样式、盔甲、二层和同一皮肤库，不要求先迁移，也不把旧数据登记成 Beta 实例。明确切换样式或添加盔甲时，可按随包的精确版本模板补齐此前已移除的原生部件；未知版本、休止绑定或共享冲突不会使用其它版本替代。V2.3.4 八头按钮继续控制原“面部兼容”骨骼。2.3.1／2.3.4 没有增强二层3D参数；旧式盔甲沿用原纹饰图，2.4.0 起的原生选择器可调材质、纹饰及颜色。换肤按实际图像通道替换，并为所选模型隔离材质引用。

通过 Blender 偏好设置的“插件 / Add-ons”菜单选择“从磁盘安装”，安装 `BlockLoom_V0.1.40-Beta.zip`。本包采用用户插件格式，模块名为 `oxal_mc_studio`；展开插件条目后，右上角直接显示 Blender 原生“卸载”按钮，启用或停用状态均可卸载。此前 0.1.0–0.1.2 的扩展格式版本须先从“获取扩展”的已安装条目菜单卸载，再安装本包，避免两个 OXAL 同时登记。个人资产库保存在插件安装目录之外。VS Code 的开发链接仍由开发工具管理，不通过卸载删除源码目录。

从使用 `core.py` 的旧版升级时，先导出或备份旧插件目录内的个人预设，再卸载旧条目，完全退出 Blender，重新打开后安装新版。1.0.196 的 `sky_presets` 位于旧插件目录内，须在卸载前另存；当前 Beta 个人库位于安装目录外。同一会话中仅停用旧版不会清除已加载的 Python 子模块，可能出现 `cannot import name 'commands' ... core.py`；遇到此错误应退出并重开 Blender 后重新安装／启用，不要从旧包复制 `core.py`。此条件在 4.5、5.0、5.1、5.2 都可能出现。修订安装包包含显式 `oxal_mc_studio/` 目录条目，保证 Blender 原生覆盖安装能识别并清理旧包目录；会话缓存仍需通过重启释放。

新导入的白珀人模使用 2.4.7 资源，合并八型头，兼容 64×64 与真实 128×128 皮肤。背饰通过插件明确切换，启用时仅追加披风或鞘翅，将对应专属骨骼加入人模主骨架，关闭时实际移除，不导入背饰模式滑柄。头部一层与二层支持人模描边；普通一键附魔默认关闭描边；盔甲的“一键添加附魔描边”和“一键添加像素格流光”按所选全部／局部直接添加并启用对应效果，单部位中继续调节参数。已有 2.4.0、2.4.2、2.4.3、2.4.4、2.4.5、2.4.6 实例继续使用其原版本资源与控制。

新建 Beta 人模默认没有盔甲网格及其闲置 Mesh／Key 数据；初始化时在发布实例前剔除模板自带的盔甲。点击添加才按所选部位创建，移除时实际删除该部位对象及无用几何依赖，不以隐藏代替移除；再次添加可恢复保留的材质引用和参数。已有动画、用户修改或外部引用冲突仍按原契约拒绝破坏性操作。旧原生人模的兼容模式继续编辑其已有部件，不自动删除旧工程网格。

旧人模迁移后若头部描边出现长尖刺，在描边设置中执行“重建描边”。共用头部改用原生固定厚度求解，保留原有表情、Action／NLA 和皮肤；已有描边只通过明确操作更新，不在播放或渲染时重建。

迁移或多实例导入后的一层身体、手臂及腿也参与描边。来源角色解析兼容 Blender 追加时的数字重名后缀；仍先核验根和对象的实际归属，同一角色重复时拒绝操作，不按显示名接管外部对象。

2.4.3 头部的闭眼盖片包含末段微深度修订，避免五种头型完全闭眼时的盖片共面；保留原 141 个形态键、统一皮肤材质与眼球眉毛。已有 2.4.3 实例可在人模功能中执行“修复头部闭眼叠面”，只处理已核验的原生头部；自定义头部结构不会被覆盖。修复前需移除头部描边，再按需重新添加。

2.4.5 在共用单头结构中，为 0–6 型左右眉毛使用 0.0003 的额外局部深度间距，保留八型切换及全部眉毛表情；7 型不增加眉毛。新资源继承闭眼盖片修订，不改变皮肤 UV、眼球及独立嘴巴。

2.4.6 修正 0–6 型长上眼皮的额头取样：28 个盖片使用对应眼位的额头行，保留原 U 列、网格和形态键。128 分支的动态眼皮、眼球与眉部保留局部 UV 岛，不再统一投影而跨行采样；静态头壳的 HD 细节保留。换肤仍需按实际眼位选择头型，内置史蒂夫对应 T5；不会把一张皮肤强行适配所有眼位。已有 2.4.5 实例通过确认后的旧人模迁移创建新版，旧实例及动画归档保留。

2.4.7 将闭眼背景覆盖面与移动眼皮短条分开取样，清理 0–6 型静态额头上的重复眉线，保留下移后的闭眼线及睁眼显示；7 型保持无眼部结构。64／128 分支分别保留原生 UV 精度，不修改皮肤图片、原网格、141 个形态键、权重或骨骼。已有 2.4.6 实例通过确认后的旧人模迁移创建新版，旧合集、Action／NLA 和同名通道动画归档保留。

盔甲普通一键附魔默认使用经典附魔；额外效果通过“一键添加像素格流光”和“一键添加附魔描边”直接启用。已有像素格流光和关键帧动画继续保留；效果开关已有动画时，直接添加操作会明确提示冲突，不覆盖原动画。

普通一键附魔的初始亮度为 0.73。像素格流光另有亮度倍率，默认倍率使基础亮度 0.73 对应发光强度 2；已有亮度和动画继续保留，旧像素材质通过明确重新应用或准备后接入倍率。

附魔效果也可用于外部导入模型和普通 Blender 对象。物体模式选中网格、带填充或倒角的曲线、文字等表面对象后使用同一区域的“一键附魔”；选中骨架或父物体时处理其可渲染子对象。外部对象使用独立的原生参数控制器，支持多材质、透明图片、无 UV、纯色／程序材质和几何节点材质输出；没有图片像素坐标时使用固定原生网格流光。共享材质通过物体级私有覆盖隔离，原模型、骨架、形态键和动画保持，原几何节点组不改写。独立描边读取原生变形后的表面，默认不开启，可单独添加、调色、调粗细或移除；取消材质附魔保留独立描边。原本没有材质槽的对象会先建立本地数据副本以避免影响其它共享使用者。

新建的外部附魔参数和附魔原生时间对象统一放在当前场景的“附魔参数”合集中；人模参数对象默认在各视图层隐藏，侧栏仍可编辑，驱动与动画继续生效。资产库新导入的方块、物品、特殊资产和图片资产统一放在“资产库”组织合集下，并保留每个实例自己的子合集。组织合集使用场景精确引用，不接管用户同名合集；已有工程对象不自动搬动，移除单个资产不会删除组织合集或其它实例。

图片物品、资产库普通物品和武器可明确准备像素 3D 凹凸，与附魔及描边共同使用；图片物品首次添加描边会直接启用，重复更新保留用户材质槽并回收可确认的旧描边尾槽。已有描边开关动画时不覆盖动画通道。外部网格使用“添加3D凹凸／移除3D凹凸”，原生细分和逐面挤出产生实际几何，原模型、形态键与动画身份保持；可调内外厚度、随机高低和中心衰减。简单图片按原 UV 明度取高低，无 UV 或复杂着色器使用稳定原生噪声场。细分等级在重新添加时应用，有几何预算限制；曲线与文字的这项几何功能需用户先建立网格副本，材质附魔、流光和描边仍可直接使用。盔甲继续使用各部位自带的 3D／厚度设置。

附魔 3D 凹凸的新建默认厚度为向外 0.01、向内 0；已有参数及其动画不自动重置。人模二层和盔甲原生厚度设置保持各自的默认值。

像素凹凸的描边使用连续表面生成原参考 Solidify 外壳，保留真实像素凹凸，减少独立像素侧壁产生的内部白网格；已有物品可通过“添加／更新描边”明确更新。人模版本以 `V版本号` 显示在实例导入区，底部提示远离世界原点、手臂接近伸直时可能发生的转腰抖动。

外部效果与已登记 OXAL 资产／盔甲分别使用各自的入口和归属控制，混合选择时会提示分开操作。相机、灯光、无表面的对象、不可编辑的链接对象、跨场景共用同一个 Object，以及无法明确处理的用户着色器连接，会返回具体原因；不会强行转换模型或覆盖未知修改。原有 OXAL 资产仍保留材质包与几何重建流程，外部效果不将用户模型接管为可重建资产。

物品资产的“一键附魔”和“取消材质附魔”只处理已登记对象的原表面材质，通过对象级材质覆盖保留当前网格、形态键、UV、动画及用户附属对象；共享材质先私有复制，取消时保留用户底材调整和专用附魔 UV 身份。已受旧补丁影响的材质，可从同贴图身份或同一原图引用的已登记源材质恢复原 UV 采样。描边独立保留。PNG 物品调整网格或材质槽后，可用“添加 / 更新描边”（失效时显示“重新绑定并恢复描边”）按当前形态建立私有描边，保留自定义材质槽及附属物；未使用的自定义槽不额外附魔。旧描边修改器或驱动无法精确核验时明确拒绝，不自动接管用户数据，也不把当前形态重新登记为原版可重建几何。

人模面板提供“迁移旧版人模（2.3.1+）”。在物体模式选择已核对版本的旧白珀人模，确认窗口会说明来源和隐藏范围；确认后新建当前插件人模、沿用主皮肤和初始样式，独立复制同名骨骼关键帧与普通 NLA Clip，将旧人模原合集放入新建的“旧人模”归档合集，并在所有视图层排除该合集。旧对象、网格、可见性驱动及动画均保留，不逐部位设置隐藏，也不接管为新版资源；不匹配通道会提示跳过，复杂 NLA、混合其它物体的旧合集、未知结构及驱动冲突明确拒绝。确认后姿态、动画或视图层状态改变时需要重新确认。胳膊／腿样式无法唯一识别时，可在确认窗口明确选择；外部物品和约束不自动重绑。

迁移确认窗口显示目标人模 2.4.7；最近的共用单头完整工程及具备有效实际归属登记的旧 Beta 实例也可迁移。当前版本、未知版本及复制后登记失效的 Beta 实例不会被猜测接管。

人模皮肤库默认提供原版史蒂夫（Steve）和艾莉克斯（Alex），无需联网或先入库；刷新列表后仍保留这两个内置条目。选择皮肤沿用现有换肤操作，不自动修改胳膊样式。

新版与旧人模兼容模式共用“皮肤库／最近使用”列表，左侧选择皮肤、右侧应用或入库；点击对应页签或刷新后载入列表。最近使用按具体人模独立保存，默认皮肤恢复不清空记录，换肤失败不写入记录。

视口选择人模的骨架或网格时，实例列表和功能区跟随实际选中目标；点击列表行通过同一人模操作入口选择该实例。样式区合并为一个表单，所选人模使用当前值，未选人模时保留导入初始选项。红温位于应用样式按钮上方；头型仍使用人模原生控制器，不重复提供面板头型按钮。

旧人模兼容模式同样显示名字、腿部固定、脚腕固定和红温。腿部固定调整原有原生约束；脚腕固定改变初始父级绑定，已有 Action／NLA 或外部共享骨架数据时拒绝改变绑定，同值不阻止其它设置。名字缺失时，明确开启才追加经过头部休止绑定核验的原版名字组件，不修改场景中其他文字。

旧人模的样式及固定开关在菜单选定时立即提交，不需要统一应用按钮。打开“人模功能”时明确准备该实例的原生红温通道，保留原值；此后拖动和插入关键帧直接使用原生数据。已知 196 红温驱动按实际源字段接续，不把它们当作未知用户驱动。未初始化实例的“红温…”会准备后直接打开实时滑条；停用插件后原生效果仍有效。用户的未知驱动或动画冲突不会被覆盖，失败恢复本次修改。


资产库首次展开自动加载目录，切换分类或提交搜索后自动更新，搜索支持回车并跨分类检索；折叠后重新展开复用已加载结果，手动刷新继续保留。

新导入的方块、物品及 PNG 图片资产支持 OXAL 自有 PBR 资源包替换，无需安装其它插件。资源包管理区域可入库 ZIP、刷新列表、应用到选中资产、恢复原图及设置后续导入；解析格式可选 lab PBR 1.3（默认）或 old PBR，支持同族 `_n`、`_s`、`_a` 配图，其中 `_a` 优先。基础色与配图分别读取自身的 `.png.mcmeta` 动画，物品几何使用有效动画帧的透明轮廓并集。已有资产通过“升级所选资产材质 / PBR”明确升级；资源包应用、恢复原图和升级保留附魔与原生动画，遇到未知修改时明确拒绝覆盖。

世界中的普通实心方块和无特殊控制器的生成式物品（如甜菜种子）不显示额外根框；树苗等植物通过实际网格的原生包围框显示线框，物体原点及操作支点保留在底部基准，不再为根框把模型下移半格。不新增框物体，不修改网格、UV 或动画；普通物品保持原有网格坐标和操作支点；骨架根、PNG 网格根及展示框／物品栏变换保留原有规则。已有实例通过“修复 / 升级 Beta 实例”明确更新；用户手动调整、显示动画及未知冲突不会被覆盖。

草方块等模型的同向共面覆盖层使用单一原生表面混合，避免透明覆盖面在 Eevee 中遮黑底层。各层保留独立贴图、PBR、动画与材质包身份；旧实例通过明确修复合并，保留实际旧贴图和可兼容的用户节点，遇到身份缺失、多义或未知动画时拒绝覆盖。

PBR 解析节点使用用户提供的 Crafter 不可变资源，来源及校验信息保存在 `asset/library/pbr/SOURCE.json`；资源包管理与替换业务由 OXAL 独立实现，不提供调用 Crafter 换包的专用入口。

## 源码目录

- `core/`：EMT 消息、调度、运行时及执行适配。
- `business/`：按天空、人模、物品栏、资产、附魔、描边分组的业务实现。
- `util/`：跨业务共用的资源、动画、节点等辅助能力。
- `module/`：业务登记与 EMT 接入；`operation/`：Blender 操作入口；`ui/`：界面。
- `asset/`：随包资源；`.dev/`：本地调试环境和临时输出。测试按需创建，文件在扩展名前、文件夹在名称末尾加 `_test`，由 Git 和打包规则自动排除，用完清理。

## 构建用户插件安装包

使用 Python 3.11+ 在源码根目录执行 `python tool/build_addon.py --output .dev/dist/BlockLoom_V0.1.40-Beta.zip`。构建器使用标准库，默认通过 Git 核对正式文件清单；遇到未跟踪的运行文件会拒绝打包。开发期间需要交付尚未加入 Git 的正式新文件时，逐项传入 `--include-untracked 相对路径`，不接受被忽略的文件或测试文件。无 Git 的干净源码副本通过 `--source 目录 --file-list 清单.json` 提供明确的运行文件清单（JSON 相对路径数组）；不依赖本机测试数据补足源码。

构建器校验版本、资源哈希、包结构及 ZIP 内容，不覆盖已有候选。生成用户插件格式 ZIP，包含显式包目录条目，不包含扩展清单、开发环境或测试文件。目录条目参与 Blender 覆盖安装的包根识别，不能在重新压缩时丢弃。

较大的 JSON 与 Python 文件仅在 ZIP-LZMA 确实更小时使用该标准容器压缩；解压后的文件字节不变，安装后运行不需要 LZMA 依赖。

维护资源容器时，可在开发依赖环境执行 `python tool/recompress_blend.py 原文件.blend 新文件.blend`。该离线工具使用开发依赖 `zstandard`，保留独立首尾元数据帧、原生 seek 表和至多 8 MiB 的中间块；保存前按两种解码路径核对完整载荷。普通构建、安装及使用不调用此工具，也不需要先运行它。

## ShuliNone 的重构工作

本次重构由 [ShuliNone](https://github.com/ShuliNone) 主导，为各模块重新搭建了共同的开发基础：

- **模块化架构**：分离 UI、Operator、模块接线与业务工具，让界面和实际功能可以分别维护。
- **自有 Bus**：通过 Topic 与 EMT 请求连接各模块，提交后由 Blender 主线程自动调度，结果延后回调；统一生命周期清理，并接入 Blender 原生撤销流程。
- **资源导入优化**：合并同源资源读取，支持天空复用、人模与物品栏独立实例导入，并处理导入失败时的状态恢复与新增数据清理。
- **界面与开发规范**：迁移四个模块的 UI，沿用 Blender 原生侧栏布局；将 Bus、资源导入和项目协作约定整理为可复用的 Skills，便于后续开发者继续接入功能。

天空、人模与资产库使用独立资源身份和持久参数，通过原生驱动、节点、约束与关键帧播放动画。渲染期间拒绝业务修改并暂停请求调度；渲染结束后的首个安全轮次取消此前未完成的请求，不自动重放，用户可重新提交。

已有天空的工程先打开、再启用插件时，Blender 可能保留旧的 RNA 驱动解析缓存；界面会提示点击“加载 / 激活”恢复该实例的输入绑定。插件登记不访问场景，也不自行扫描修复工程；用户明确提交的激活操作由 EMT 调度执行。

物品栏保留独立导入的第一人称与第三人称视角，通过原有骨骼及原生属性控制；不接入战斗和游戏模拟系统。云数量与阴影范围通过明确操作调整，范围外无用对象实际移除；云移动、昼夜与光照仍使用原生动画。生物资产保留开发中占位。开发与交付遵循仓库内 `.agents/skills/` 的规范。
